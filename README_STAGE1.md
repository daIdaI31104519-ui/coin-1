# coin-1 実装①：人工BTC研究 → JSON保存・読み戻し

対象：`設計/実装01_最小作業仕様.md` v0.1（2026年11月4日正式採用）

このコードは、**実装①だけ**の最小プロトタイプです。実市場データ、実取引、Telegram、日本語研究日記、継続稼働の機能はありません。

## 構成

- `src/coin1_stage1.py`：人工データ検証、時刻順の研究判定、仮想売買、JSON保存・読み戻し
- `tests/fixtures/btc_synthetic_1h.csv`：正式仕様の人工BTC 1時間足8本
- `tests/test_stage1.py`：T01〜T08、および先読みの補助検証
- `.gitignore`：実験出力とローカル環境ファイルをGit管理から除外する候補

## 実行方法

Python 3.10以上を想定。外部パッケージは不要です。リポジトリのルートにファイルを置いた状態で、次のコマンドを実行してください。

```bash
python -m unittest discover -s tests -v
python src/coin1_stage1.py run --data tests/fixtures/btc_synthetic_1h.csv --out-dir outputs
```

実行後に表示されるJSONの `record_path` を使って、別プロセスで読み戻せます。

```bash
python src/coin1_stage1.py read --record outputs/<表示されたrun_id>.json
```

読み戻しは研究処理を再実行せず、保存記録だけを検証します。

## 時系列上の注意

07:00開始足の始値だけを07:00で仮想決済価格の参照値として使い、高値・安値・終値・最終出来高は07:00の判断に使いません。入力CSV全体のSHA256は出典照合用メタデータであり、過去時点の判断や品質判定には利用しません。実際の配信遅延・約定可能性は未検証です。

## 保存・中断上の注意

1実験1JSON。開始時に `running` を保存し、終了時に `completed` あるいは `failed` を保存しようとします。ストレージ自体が故障した場合は失敗JSONを残せないことがあり、標準エラー出力と終了コードを使います。書き換えは一時ファイルを経由しますが、電源断への完全な耐久性や常時監視は保証しません。

同じ実験IDの保存先を排他的に確保します。中断が最初の `running` 保存より早ければ空ファイル、それ以降なら `running` が残り得ます。いずれも完了とは扱わず、同じIDで自動再開・上書きせず、新しいIDで実行してください。`completed` 候補は一時ファイルから読み戻して検証した後に公開します。公開後の電源断・保存装置の故障や第三者による改変まで、読み戻し時の整合検査だけで保証するものではありません。

実装②で読み取りやすくするため、実験ID・イベントID・判断根拠・版識別・実行状態を記録します。`source_revision.file_sha256` はコード本体のSHA256で、ローカル未コミット試験では `git_status: unverified` と明示します。
